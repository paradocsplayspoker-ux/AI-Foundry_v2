The **Providers** page in Settings is your central hub for every API key saved in your workspace. From here you can see the status of each credential at a glance, run a live test, wire a key to a specific agent, add backups for the same provider, or remove keys you no longer need. This page explains each of those operations and describes what happens when a credential fails mid-session.

<Tip>
  Name your credentials descriptively — for example `prod-openai-key-1`, `staging-anthropic-claude`, or `teamlead-groq-key` — so you can identify them instantly without having to decode a masked key string.
</Tip>

## Viewing all credentials

The Providers table shows one row per credential with the following columns:

| Column | What it shows |
|--------|---------------|
| **Name** | The label you chose when creating the credential |
| **Provider** | The AI provider (e.g., OpenAI, Anthropic) |
| **API Key** | The masked key — only the last few characters are visible |
| **Status** | `Active`, `Untested`, or `Error` based on the last test result |

## Testing a credential

Click the **Test** button on any row to send a lightweight validation request to the provider. AI Forge updates the **Status** column in real time:

- ✅ **Active** — the key is valid and the provider accepted the request
- ❌ **Error** — the key was rejected; hover the status badge to see the provider's error message

Run a test any time you suspect a key has been revoked, has hit a quota limit, or was recently rotated.

## Assigning a credential to an agent

By default, agents use the workspace-level default credential for their provider. To assign a specific credential to one agent:

<Steps>
  <Step title="Open the agent's settings">
    Navigate to the agent you want to configure and click the **Settings** (gear) icon on its card or inside the agent panel.
  </Step>
  <Step title="Choose a provider credential">
    Find the **Provider Credential** dropdown and select the named credential you want this agent to use exclusively.
  </Step>
  <Step title="Save">
    Click **Save**. The agent will now route all its requests through the assigned credential, overriding any workspace default.
  </Step>
</Steps>

## Adding a second credential for the same provider

You can add as many credentials as you like for a single provider. This is useful when you want to:

- **Distribute load** — two OpenAI keys means requests alternate between them, effectively doubling your per-minute token budget
- **Separate billing** — keep a personal key and a company key distinct within the same workspace
- **Maintain a hot spare** — keep a backup key ready so you can promote it instantly if the primary is revoked

To add another credential, click **Add Provider**, select the same provider, give the new credential a distinct name, and paste the second key. You can then assign each credential to different agents or leave both in the shared pool.

## Removing a credential

Click the **Delete** (trash) icon on a credential's row and confirm the prompt. Note that:

- If the credential was assigned to one or more agents, those agents will fall back to the workspace default credential for their provider.
- If no default exists after deletion, the affected agents will show a configuration error until you add a replacement credential.

<Warning>
  Deleting a credential is immediate and cannot be undone. Make sure no agent depends solely on that key before removing it, or assign a replacement credential first.
</Warning>

## What happens when a credential fails

AI Forge isolates every provider connection independently. If a credential becomes invalid mid-session — for example, the key is revoked or the provider returns a rate-limit error — the following happens:

1. The agent using that credential surfaces the error directly in its chat thread, showing the provider's error message.
2. The credential's **Status** in the Providers table updates to **Error**.
3. Every other agent in your project continues running normally — a single failing credential never crashes or pauses the rest of your workspace.

To recover, either fix the key (by deleting and re-adding it with a valid value) or reassign the affected agent to a working credential.
