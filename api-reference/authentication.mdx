Every request to the AI Forge API must be authenticated. The API uses the standard Bearer token scheme — you include a secret token in the `Authorization` header, and the API validates it before processing your request. There are no cookies or session-based flows; each request is independently authenticated.

## Generating an API Token

<Steps>
  <Step title="Open Settings">
    Navigate to **Settings → API Tokens** in your AI Forge workspace.
  </Step>
  <Step title="Create a Token">
    Click **New Token**, give it a descriptive name (for example, `ci-pipeline` or `dashboard-readonly`), and confirm.
  </Step>
  <Step title="Copy the Token">
    Copy the token immediately — it is shown only once. If you lose it, you will need to revoke the old token and generate a new one.
  </Step>
</Steps>

<Warning>
  Treat your API token like a password. Never commit it to source control, log it, or expose it in client-side JavaScript that ships to end users.
</Warning>

## Sending the Authorization Header

Add your token to every request using the `Authorization` header:

```
Authorization: Bearer <your-api-token>
```

### curl example

```bash title="Authenticated request with curl"
curl https://api.aiforge.app/api/projects \
  -H "Authorization: Bearer <your-api-token>"
```

### fetch example

```js title="Authenticated request with fetch"
const API_TOKEN = process.env.AIFORGE_API_TOKEN; // never hard-code your token

const response = await fetch("https://api.aiforge.app/api/projects", {
  headers: {
    Authorization: `Bearer ${API_TOKEN}`,
    "Content-Type": "application/json",
  },
});

if (!response.ok) {
  const { error } = await response.json();
  throw new Error(`${error.code}: ${error.message}`);
}

const data = await response.json();
```

## Authentication Errors

| Status | Code | Meaning |
|--------|------|---------|
| `401` | `unauthorized` | The `Authorization` header is missing, malformed, or the token has been revoked. |
| `403` | `forbidden` | The token is valid but your account does not have permission to perform this action on the requested resource. |

### 401 — Invalid or missing token

```json title="401 Unauthorized"
{
  "error": {
    "code": "unauthorized",
    "message": "Missing or invalid API token."
  }
}
```

If you receive a 401, verify that:
- The `Authorization` header is present and formatted as `Bearer <token>` (note the space).
- The token has not been revoked in **Settings → API Tokens**.
- You are targeting the correct base URL (`https://api.aiforge.app/api`).

### 403 — Insufficient permissions

```json title="403 Forbidden"
{
  "error": {
    "code": "forbidden",
    "message": "You do not have permission to perform this action."
  }
}
```

If you receive a 403, check whether your user account has the necessary role on the target project. API tokens inherit your account's project-level permissions — they cannot be granted more access than you currently have.

<Note>
  API tokens carry the same project-level permissions as the user account that generated them. If your account is a **Viewer** on a project, your API token cannot create or modify resources in that project either.
</Note>

## Revoking a Token

To revoke a token, go to **Settings → API Tokens**, find the token by name, and click **Revoke**. Revoked tokens are rejected immediately — any in-flight request using a revoked token will receive a `401` response.

<Tip>
  Rotate your tokens regularly and use separate tokens for each integration (for example, one for CI, one for your dashboard). This way, you can revoke a single token without disrupting other workflows.
</Tip>

## Provider Credentials

Provider credentials store the API keys your agents use to call AI providers such as OpenAI, Anthropic, or Google. Credentials are encrypted at rest and your API key is never exposed in any API response after it has been saved.

### List providers

Retrieve the list of AI providers supported by AI Forge, along with the fields required to configure a credential for each one.

```
GET /api/providers
```

#### Example request

```bash title="List supported providers"
curl https://api.aiforge.app/api/providers \
  -H "Authorization: Bearer <your-api-token>"
```

#### Example response

```json title="200 OK"
{
  "providers": [
    {
      "id": "openai",
      "name": "OpenAI",
      "models": ["gpt-4o", "gpt-4o-mini", "gpt-3.5-turbo"],
      "requiredFields": ["apiKey"]
    },
    {
      "id": "anthropic",
      "name": "Anthropic",
      "models": ["claude-3-5-sonnet-20241022", "claude-3-haiku-20240307"],
      "requiredFields": ["apiKey"]
    },
    {
      "id": "google",
      "name": "Google Gemini",
      "models": ["gemini-1.5-pro", "gemini-1.5-flash"],
      "requiredFields": ["apiKey"]
    },
    {
      "id": "custom",
      "name": "Custom (OpenAI-compatible)",
      "models": [],
      "requiredFields": ["apiKey", "baseUrl"]
    }
  ]
}
```

### Store a credential

Save a provider API key so agents can use it for inference without exposing the key to the browser.

```
POST /api/credentials
```

<Warning>
  AI Forge stores provider credentials in encrypted form. Your API key is **never** returned in any subsequent API call — only the credential `id` is exposed, which you then reference when creating or updating agents.
</Warning>

#### Request body

<ParamField body="provider" type="string" required>
  The provider ID (for example, `"openai"`, `"anthropic"`, `"google"`). Use `GET /api/providers` to see all supported values.
</ParamField>

<ParamField body="name" type="string" required>
  A friendly label for this credential (for example, `"Production OpenAI Key"`).
</ParamField>

<ParamField body="apiKey" type="string" required>
  The provider API key to store.
</ParamField>

<ParamField body="baseUrl" type="string">
  Required when `provider` is `"custom"`. The base URL of your OpenAI-compatible endpoint.
</ParamField>

#### Example request

```bash title="Store an OpenAI credential"
curl -X POST https://api.aiforge.app/api/credentials \
  -H "Authorization: Bearer <your-api-token>" \
  -H "Content-Type: application/json" \
  -d '{
    "provider": "openai",
    "name": "Production OpenAI Key",
    "apiKey": "sk-..."
  }'
```

#### Example response

```json title="201 Created"
{
  "credential": {
    "id": "cred_01hwbc1a2b",
    "provider": "openai",
    "name": "Production OpenAI Key",
    "createdAt": "2024-05-10T09:00:00Z"
  }
}
```

Use the returned `id` (for example, `cred_01hwbc1a2b`) as the `credentialId` when [creating or updating agents](/api-reference/agents).

#### Error cases

| Status | Code | Cause |
|--------|------|-------|
| `400` | `validation_error` | `provider`, `name`, or `apiKey` is missing, or `provider` is not a recognised value. |
| `401` | `unauthorized` | Invalid or missing API token. |
